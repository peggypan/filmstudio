## 架构决策

### 1. Monorepo 架构 (Turborepo)
**决策时间**: 2026-03-13  
**决策内容**: 使用 Turborepo 管理前后端代码  
**原因**:
- 统一依赖管理，避免版本冲突
- 共享类型定义和工具函数
- 统一构建和部署流程
- 代码复用率高

**替代方案**: 分开两个仓库  
**未选原因**: 代码同步麻烦，类型共享困难

---

### 2. 前端技术栈

#### React 18 + TypeScript
**决策时间**: 2026-03-13  
**原因**: 类型安全，生态成熟，团队熟悉

#### Vite (而非 Create React App)
**决策时间**: 2026-03-13  
**原因**:
- 启动速度快 (秒级 vs 分钟级)
- HMR 热更新更快
- 配置简单
- 原生 ESM 支持

#### Ant Design 5
**决策时间**: 2026-03-13  
**原因**:
- 企业级UI组件库
- 中文文档完善
- 支持主题定制
- 表单、表格等组件功能强大

#### Zustand (而非 Redux)
**决策时间**: 2026-03-13  
**原因**:
- 学习成本低
- 代码量少
- 不需要模板代码
- 完全支持 TypeScript

#### React Query
**决策时间**: 2026-03-13  
**原因**:
- 数据获取专用
- 自动缓存和失效
- 支持乐观更新
- 减少重复请求

#### Fabric.js
**决策时间**: 2026-03-13  
**原因**: 分镜编辑器需要画布功能，Fabric.js 是 React 生态中最成熟的选择

---

### 3. 后端技术栈

#### NestJS (而非 Express)
**决策时间**: 2026-03-13  
**原因**:
- 模块化架构，适合大型项目
- 内置依赖注入
- TypeScript 原生支持
- 企业级框架，生态完善

#### Prisma (而非 TypeORM)
**决策时间**: 2026-03-13  
**原因**:
- 类型安全的数据库操作
- 自动生成的类型定义
- 迁移管理方便
- 查询性能优化

#### PostgreSQL
**决策时间**: 2026-03-13  
**原因**:
- 关系型数据为主（用户、项目、剧本等）
- JSONB 支持灵活的剧本存储
- 成熟稳定，扩展性好

#### Redis
**决策时间**: 2026-03-13  
**用途**: 会话缓存、热点数据缓存、任务队列

#### MinIO
**决策时间**: 2026-03-13  
**用途**: 对象存储（用户头像、分镜图、音频文件）
